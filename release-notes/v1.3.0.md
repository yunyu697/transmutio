# Transmutio 1.3.0

次版本（`1.3.0`）。界面按「实际使用」重构为**工作方案 A（工作台式）**，分五期落地，
另修掉浅色主题启动时的首帧跳色。属于结构性改动：信息架构、参数面板默认形态、
任务区位置、输出位置与主题模型都变了。设置与预设会自动迁移，不丢数据，但部分
入口与设置项的语义和以前不同，升级前请先看「行为变化」。

## 为什么是 1.3.0

同一件事有三套入口（首页速览卡、侧栏分区子项、最近使用），用户要选两次才能开始；
参数面板把十组参数一次铺开，常用项被淹；任务中心占着主区一块固定高度；
输出位置只在设置里改，改完还得回来。这次按工作台式重组：**选方法只留一个来源，
其余按需展开**。改动跨五个层面且行为有变化，因此走次版本而不是补丁版本。

## 五期改动与实测

### 1. 入口合一：侧栏一层分区 + 单一方法列表

- 删除首页速览卡（`HomeView`，约 95 行）、方法网格之外的分区子项与「最近使用」；
  启动直接落在当前分区的方法列表，点品牌图标/名称也回到列表。
- `catalog` 去掉只服务速览卡的 `quick` / `formats` / `scenes`；设置去掉 `recentMethods`。

真机实测（真实 WebView2 窗口，`verify:real` 1.2–1.4）：

| 项目 | 实测 |
| --- | --- |
| 侧栏分区层级 | `side-group` = **1**；分区 = 视频 11 / 音频 5 / 图片 9 |
| 旧入口残留 | 分区子项 0 / 旧子项 0 / 最近使用 0 / 速览卡 0 / 速览区 0 |
| 主区方法列表 | **11 张卡片**，标题「视频」，单一列表 |
| 侧栏宽 | **236px** |

### 2. 参数默认只露常用项

- `Group` 增加 `collapsed`：次要参数改为原生 `details/summary` 折叠行，标题常驻、点开即用，
  键盘与读屏行为跟随系统控件。
- 视频：默认展开目标格式 / 画质与尺寸 / 输出命名 **3 组**，编码器 / 画面调整 / 变速 / 音频 /
  音量 / 高级 **6 组收起**；音频 3 组折叠；图片的裁剪按当前方法决定是否收起，方向默认收起。

真机实测：6 个折叠行均为 `36px`（summary 自身 `35px`，无内容泄漏），点「编码器」标题后
展开到 `874px`；展开/收起不改变其它分组位置。

### 3. 任务中心降为底部队列条

- 新增 **44px** 常驻队列条（运行 / 排队 / 完成 / 失败 + 当前任务进度 + 暂停），抽屉默认收起，
  点条展开完整任务列表；任务卡片改为自适应多列。
- 设置项 `taskCenterOpen` 改为 `taskDrawerOpen`（默认 `false`）。

真机实测：队列条高 **44px**，底边 `850px` == 状态栏顶 `850px`（正好在其上方，不重叠）；
点开后抽屉高 **320px**，再点收起、`aria-expanded` 回到 `false`。

### 4. 输出位置移到开始按钮上方

- 新增共用 `OutputDirBar`：自定义目录时显示完整路径与「更改」，并额外给出「使用源文件夹」；
  已是源目录时该按钮不出现。侧栏里重复的输出位置摘要删除，`bottombar` 改为两行布局。
- 「使用源文件夹」只切模式，**保留上次记住的自定义路径**，再切回自定义即可复用。

真机实测：输出行底 `756px` < 开始按钮顶 `764px`；自定义后按钮为 `["更改","使用源文件夹"]`；
点「使用源文件夹」后 `outputDirMode=source`、按钮消失、路径显示「与源文件相同目录」，
刷新后仍保持，且 `outputDir` 里的自定义路径未被清空。真实窗口点「更改」会打开系统
「选择文件夹」对话框（class `#32770`），ESC 可关闭。

### 5. 明暗与配色拆成两个正交维度

- `brightness`（浅色 / 深色 / 跟随系统）只决定亮度基调；`palette`（石墨 / 深海 / 暖砂 / 苔原）
  是一整套完整色板（背景、表面、边框、主次文字、强调、状态与悬停选中态）。两者分别持久化，
  以 `data-theme` + `data-palette` 组合，17 个颜色 token 全部由色板给出。
- 系统切换「跟随系统」时只改亮度，不换配色。

真机实测：浅色 + 深海 `--ff-bg=#E9F1FB`、深色 + 苔原 `#0A1210`、浅色 + 暖砂 `#F7F1E8`，
切换即时生效（无需刷新）；刷新后深色 + 苔原保持。实渲染对比度
浅色 + 深海 14.71 / 16.75 / 4.85，深色 + 苔原 16.55 / 14.64 / 5.49。
`verify:theme` 对 4 套配色 × 2 种亮度做 WCAG 校验，**72/72 通过**。

## 首帧跳色：根因与修法

**根因**：窗口按 `tauri.conf` 里的静态 `backgroundColor: "#0A0E14"` 出现，而 WebView2 首绘
要等到前端加载并应用设置之后。浅色用户启动时，会先看到约 **0.85s 的深色空窗**，再整屏
跳到浅色——表现为「闪白/跳色」的反向版本。这不是 CSS 变量没生效，而是窗口底色在
主题数据读到之前就已经定死。

**测量**：`PrintWindow(hwnd, hdc, PW_RENDERFULLCONTENT)` 直接抓窗口表面逐帧采样亮度
（不受窗口叠放与焦点影响），采样点覆盖窗口 8%–92% × 10%–90% 的 24×14 网格。

| | 修复前 | 修复后（1.3.0） |
| --- | --- | --- |
| 浅色启动 | 1.08–1.93s 持续 YAVG≈29.7（深色空窗）→ 跳到 222 | **293ms 首帧 y=240，中心像素 233,241,251 = `#E9F1FB`** |
| 深色启动 | — | **361ms 首帧 y=13.6，中心像素 10,14,20 = `#0A0E14`** |
| 越界帧 | 约 850ms 的暗帧 | **0 帧**（浅色无暗帧 / 深色无亮帧） |

**修法**：前端切换主题时把 `theme / bg / caption` 落盘到
`%APPDATA%\app.transmutio.desktop\window-chrome.txt`（GPL 变体为 `app.transmutio.desktop.gpl`）。
`run()` 里在 `tauri::generate_context!()` 之后、`Builder` 之前读取该文件，用
`config_mut()` 改写 `windows[0].background_color` 与 `theme`——窗口第一次出现就是正确颜色。
标题栏颜色（配置里表达不了）在窗口创建后由 `apply_saved_chrome` 补齐。

否决的中间方案：`visible:false` + 手动 `show()`。窗口出现时间从 ~1.05s 推迟到 ~1.8s，
且后台启动时 Windows 焦点保护会阻止抢焦点，用户会看到桌面空等更久，收益为负。

## 行为变化（升级前请知悉）

- **选方法只留一个来源**：首页速览卡、侧栏分区子项、最近使用都已移除；启动直接进入当前
  分区的方法列表。以前记在「最近使用」里的方法不会再出现在侧栏。
- **输出位置只在开始按钮上方改**：设置页仍可设默认模式（源目录 / 自定义），但侧栏不再显示
  输出摘要；在底部条点「更改」即时改，点「使用源文件夹」一键切回。
- **任务区默认收起**：常驻的是 44px 队列条，完整列表点开抽屉；旧的 `taskCenterOpen` 设置
  不再生效，新键为 `taskDrawerOpen`。
- **主题设置拆分**：旧 `theme`（light/dark）自动折算为 `brightness`，配色默认石墨；
  明暗与配色可任意组合，分别记住。
- **窗口配色缓存文件**：`%APPDATA%\<identifier>\window-chrome.txt`，删除后下次启动回到
  深色 + 石墨默认，不影响其它设置。

  本机 PATH 上是 GPL full build 时，LGPL 变体会正确停在引导页；脚本会注入
  `samples/_dl` 下带 `lgpl` 的 ffmpeg（或 `VERIFY_FFMPEG` 指定的路径）后继续。
- 版本文件：`version:check` 通过（`1.3.0`）。

## 已知限制（不美化）

- **安装包未签名**：无 Authenticode、无 Apple Developer ID / 公证；更新包 `.sig` 是 minisign，
  与应用签名不是一回事。
- macOS / Linux 由 CI 构建，本版仍无实机运行验证。
- FFmpeg 不随包分发；本次未改动转码链路与预设格式。
