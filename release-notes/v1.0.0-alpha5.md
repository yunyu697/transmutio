# Transmutio 1.0.0-alpha5

预发布（prerelease），不建议日常使用。

## 本阶段做了什么

第 5 块的头两项，按依赖顺序先做图片侧：

1. **EXIF 元数据写入**（图片 › EXIF 元数据写入）
   - 字段：描述 / 作者 / 版权 / 软件 / 拍摄时间 / 厂商 / 型号 / 镜头 / 方向（1/3/6/8）。
   - 只写副本，源文件不动；写完从输出文件**回读逐项比对**，不一致即失败。
   - 失败删除半成品；目标已存在拒绝并改 `name (1).ext`；空字段 / 时间格式 / 方向越界在开始前拒绝。
2. **AVIF 编码**（图片 › 图片转 AVIF）
   - 质量 1–100、速度 1–10；只写副本；**校验 ftyp/avif 签名**后才算成功。
   - 不用 FFmpeg 的原因：内置构建虽然有 `libaom-av1` / `librav1e` / `libsvtav1` 编码器，
     但 **FFmpeg 没有 AVIF 封装器**（没有 `-f avif`），产出不了 `.avif` 静图，改用纯 Rust 的 `ravif`。

## 实测

- `cargo test exif_write::` **6/6**；`cargo test avif::` **6/6**；全量 **146 passed / 0 failed**。
- 真实 JPEG 写 EXIF（p2-check `exif-write`）：640×480 不变；源 **2022 字节未改动**；
  输出 **2312 字节**；回读 8 个标签一致（含方向 6）。
- 真实 JPEG 转 AVIF（p2-check `avif-encode`）：源 **2023 字节未改动**；输出 **574 字节**，
  640×480 由 **ffprobe 独立解码确认**，压缩比 28.4%。
- 前端 `tsc --noEmit && vite build` 通过。

## 已知限制

- 两个新面板的 **UI 交互没有在真实窗口点过**（无可见 GUI 会话）；验证的是后端真实写入/编码 + 前端构建。
- EXIF：WebP 仅支持无损/扩展格式；HEIC / AVIF / JXL 写入没有真实样本验证；只写不改像素。
- AVIF：不提供 AVIF 解码（转回其它格式）；GIF 只取首帧；未做与 libaom / SVT-AV1 的质量横评。
- 安装包仍**未签名**（Windows SmartScreen / macOS Gatekeeper / Linux deb 提示），放行步骤见 README。
- macOS 无真机验证；Linux 只有容器 + Xvfb（见 alpha4 说明）。
- 工具集、光盘/ISO、Office 互转、更新器仍未开始。
