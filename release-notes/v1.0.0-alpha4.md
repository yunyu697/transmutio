# Transmutio 1.0.0-alpha4

预发布（prerelease），不建议日常使用。

## 本阶段做了什么

- **Linux 实跑验证（容器内）**：安装 CI 产出的 deb（`ubuntu:22.04`），验证
  `--version`、动态库完整性与窗口创建；结果见下文「实测」。
- **CI 增加无窗口真实转码**：`release.yml` 的 Linux / macOS 构建任务在出包后直接跑
  `headless-check`（与应用同一份任务核心 + runner 的真实 ffmpeg），报告作为 artifact 上传；
  失败不阻断出包，但结果如实记录，不把「构建成功」当作「转码成功」。
- **CI 增加 Linux 回归转码**：`ci.yml` backend 任务在单元测试后跑同一套无窗口检查，
  Linux 上的真实转码不再只靠 Windows 本机。
- **README 补「未签名构建的安装与首次运行」**：Windows SmartScreen、macOS Gatekeeper、
  Linux deb 未签名与 AppImage FUSE 的放行步骤逐条写明，并注明这些只是绕过提示，
  **不等于签名问题已解决**。

## 实测

- Linux（Docker `ubuntu:22.04`，安装 `Transmutio_1.0.0-alpha3_amd64.deb` 3,637,654 字节）：
  - `Transmutio --version` → `Transmutio 1.0.0-alpha3 (lgpl)`
  - `ldd` 缺失库条目 **0**
  - Xvfb `1280x800x24`：X11 窗口树出现 `"Transmutio" 1400x880`，7s 后进程仍存活 → `WINDOW_OK`
  - 证据层级：二进制可执行 + 窗口可创建并存活；**不含**窗口内容渲染与交互验证
- Linux / macOS 无窗口真实转码：由本次 tag 触发的 release 工作流构建任务执行，
  结论见该 run 日志与 `core-e2e-linux-report` / `core-e2e-macos-report` artifact。

## 已知限制

- **安装包未签名**（无 Authenticode / Apple Developer ID / 公证）。macOS 首次打开会被
  Gatekeeper 拦截，Windows 会出现 SmartScreen 提示；放行步骤只是用户侧操作，不是修复。
- **macOS 没有真机验证**：本机无 Apple 设备，窗口渲染、Gatekeeper 实际拦截与硬件编码
  （VideoToolbox）仍未实测；本阶段只有 CI 构建与无窗口转码。
- **Linux 只有容器 + Xvfb**：没有真实桌面会话（X11/Wayland 实机），窗口渲染与 VAAPI
  仍未实测。
- macOS / Linux 的 FFmpeg/Poppler 仍无自动下载（无可固定官方 SHA-256 的发布包）。
- Linux 只产出 deb + AppImage（RPM 不接受 `-alphaN` 版本号，不产 rpm）。
- 本阶段**没有**推进功能项（EXIF / AVIF / 工具集 / 光盘 / Office / 更新器仍是下一阶段）。
